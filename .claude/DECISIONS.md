# Журнал принятых решений

Долговременная память проекта: почему сделано именно так, что рассматривали и отклонили, чем за это платим. Новые записи сверху. Старые записи не удаляются и не переписываются: при пересмотре старой записи ставится статус `заменено ADR-NNNN` и добавляется новая.

## ADR-0002 — 2026-11-11 — Правая сторона диффа — файл с диска, если папка репозитория стоит на голове PR

- **Статус:** принято
- **Контекст:** обе стороны диффа были снимками `git show` под своей схемой URI. Языковые серверы (Pylance) такие документы не индексируют, поэтому из диффа не работали переход к определению и поиск использований. Обойти это открытием worktree в отдельном окне неудобно: основное окно открыто на основном клоне, а Pylance по умолчанию не индексирует папки, начинающиеся с точки, в том числе `.worktrees/`.
- **Решение:** если основной клон (в том числе после `git checkout --detach`) или любой worktree стоит ровно на коммите головы, а файл в нём есть и не изменён (`git status --porcelain`), правая сторона открывается как `file://`. При нескольких таких папках первой берётся та, где файл лежит в папке workspace; при равенстве — основной клон. Левая сторона остаётся снимком и несёт метку PR, поэтому дерево находит PR вкладки по её левой стороне (`TabInputTextDiff.original`).
- **Альтернативы:**
  - правая сторона всегда из рабочей копии ветки PR — отклонено: если ветка ушла вперёд или есть локальные правки, дифф показал бы не то, что в ссылке;
  - отдельная команда «открыть файл» рядом с диффом — отклонено: переход нужен прямо в диффе, а лишний клик ничего не даёт;
  - индексировать снимки — невозможно: Pylance работает только с файлами.
- **Последствия:** чтобы навигация работала, папку нужно поставить на голову PR: основной клон через `git checkout --detach`, после чтения вернуть ветку. Вкладка, открытая с файла, не следит за переключением ветки: после него справа будет уже другое содержимое. Правка справа меняет рабочую копию, на detached HEAD такие изменения легко потерять.
- **Ссылки:** `src/diff.js` (`headFile`), `src/model.js` (`parseWorktrees`, `byWorkspace`), `src/tree.js` (`revealEditor`).

## ADR-0001 — 2026-10-15 — Дерево PR в своей панели: файлы из локального git, Viewed локально, reveal в «From Links»

- **Статус:** принято
- **Контекст:** клик по `.prdiff`-ссылке в плане открывал дифф одного файла, но не показывал, где этот файл лежит в PR и что ещё изменилось. Нужна копия части расширения GitHub Pull Requests: дерево файлов PR со статусами A/M/D/R, кнопка push и подсветка в дереве файла, по которому кликнули. Расширение GitHub Pull Requests так не умеет: по ссылке оно открывает только PR целиком, а Claude Code чат вырезает `vscode://`-ссылки.
- **Решение:** своя панель в Activity Bar с разделами From Links, Created By Me, Waiting For My Review, All Open. Списки PR приходят из `gh pr list`/`gh pr view`, а файлы PR — из локального `git diff --raw -z -M <merge-base> <head>`; недостающие коммиты подтягиваются через `git fetch <remote> refs/pull/N/head <base>`. Клик по ссылке добавляет PR в From Links и раскрывает дерево до файла там. Отметки Viewed хранятся в `globalState` вместе с blob SHA файла. Push работает только для открытых PR из того же репозитория (не из форка), без force и никогда для веток из `prDiffLinks.protectedBranches` (по умолчанию `main`, `master`, `develop`, `stage`). Иначе релизный PR `stage → main` показал бы кнопку, которая пушит локальный `stage` прямо в origin. Корень репозитория для дерева и для SHA-ссылок — основной клон (через `--git-common-dir`), а не путь worktree: тогда ссылка из worktree и клик в дереве открывают одну вкладку, и ссылки переживают удаление worktree. Изменения локальных веток отслеживаются опросом `git for-each-ref` раз в 5 с, пока панель видна.
- **Альтернативы:**
  - файлы из `gh pr view --json files` — отклонено: нет старого пути у переименований и нет blob SHA, к тому же дерево могло бы разойтись с тем, что показывает локальный дифф;
  - Viewed синхронизировать с GitHub через `markFileAsViewed` — отклонено пользователем, нужны только локальные отметки;
  - reveal в любом разделе, где есть PR, — отклонено: разделы загружаются лениво, и PR из ссылки часто уже смержен, то есть в All Open его нет; From Links есть всегда, поэтому reveal ведёт себя предсказуемо;
  - `FileSystemWatcher` на `refs/heads` — отклонено: refs лежат вне workspace, общие для worktree, а packed-refs обновляются в обход файлов веток. Опрос проще и надёжнее;
  - секция в Source Control или Explorer — отклонено пользователем в пользу своей иконки.
- **Последствия:** для локальных ссылок нужны `git` и авторизованный `gh`. Дерево показывает текущую голову PR, а старая ссылка открывает дифф на своём, более раннем SHA. Отметки Viewed не видны на github.com и другим людям. Reveal переключает основной сайдбар на панель PR; если там же открыт чат Claude, панель лучше перенести во вторичный сайдбар или выключить `prDiffLinks.revealOnLinkOpen`. Push из форков и force-push недоступны.
- **Ссылки:** PR https://github.com/fallenreds/vscode-pr-diff-links/pull/1; `src/tree.js`, `src/model.js`, `src/repos.js`, `src/diff.js`, `src/github.js`, `bin/prdiff-link`.
