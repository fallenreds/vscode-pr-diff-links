# PR Diff Links

Расширение VS Code: клик по ссылке открывает **дифф файла из pull request в две колонки**. Слева база PR, справа PR, курсор на нужной строке. Это тот же встроенный дифф VS Code, что показывают Source Control и GitHub Pull Requests.

Ещё у расширения есть своя панель в Activity Bar: **дерево PR** с файлами по папкам, локальными отметками Viewed и кнопкой push. Файл, по ссылке на который кликнули, выделяется в этом дереве.

## Зачем

Когда ИИ-ассистент (Claude Code) или человек расписывает PR («функция `A` в файле `B` делает…»), читать проще, если каждая ссылка сразу открывает **изменения**, а не текущую версию файла.

Готовые варианты не подошли:

- **Чат Claude Code в VS Code** оставляет кликабельными только `http(s)`/`mailto` и обычные пути к файлам. Ссылки `vscode://…` и `file://…` он вырезает, поэтому deep-link'и других расширений (например, GitLens) из чата не открываются.
- **GitHub Pull Requests** открывает по ссылке только PR целиком, дифф отдельного файла на строке так не открыть.
- **Ссылки на github.com** уводят в браузер.

Поэтому ссылка здесь указывает на крошечный файл `*.prdiff`. Чат открывает его как обычный файл, а расширение тут же закрывает вкладку и показывает дифф.

## Как это работает

Файл `.prdiff` — это одна строка JSON:

```json
{"repo": "/abs/path/to/repo", "base": "<sha|ref>", "head": "<sha|ref>", "path": "src/app.py", "line": 42, "pr": 82, "url": "https://github.com/<owner>/<repo>/pull/82"}
```

`pr` и `url` необязательны. По ним дерево находит PR (см. «Reveal»), ссылки без них тоже работают.

Что делает расширение:

1. берёт `merge-base base head`. Это то же, что показывает вкладка «Files changed» в PR (сравнение через три точки);
2. читает обе версии файла через `git show <ref>:<path>`. Встроенный Git API не нужен, поэтому работает любой репозиторий или worktree, даже если он не открыт в окне;
3. открывает `vscode.diff`. Если файл новый или удалён, вместо отсутствующей стороны показывает пустую.

Если папки `repo` уже нет (worktree удалили после мержа), а в `url` указан репозиторий, расширение берёт его локальный клон из тех, что уже знает: папки workspace и репозитории из прошлых ссылок.

Второй триггер — URI-обработчик для мест, где `vscode://` не вырезается (Markdown preview, браузер):

```
vscode://fallenreds.pr-diff-links/open?repo=…&base=…&head=…&path=…&line=…
```

Ошибки пишутся в Output → «PR Diff Links».

## Дерево PR

Иконка PR в Activity Bar открывает панель «Pull Requests». Разделы — как в GitHub Pull Requests:

- **From Links** — PR, по ссылкам на которые кликали, новые сверху, не больше 20. Здесь остаются и смерженные, и закрытые PR;
- **Created By Me** — `author:@me`;
- **Waiting For My Review** — `review-requested:@me`;
- **All Open** — все открытые PR.

PR запрашиваются через `gh` для каждого GitHub-репозитория: из папок workspace (remote `origin`, а если его нет — первый GitHub-remote) и из репозиториев, по ссылкам из которых кликали. Раздел загружается, когда его раскрывают. Ошибка `gh` показывается строкой внутри раздела.

У PR в описании `#N · автор`, иконка и её цвет показывают состояние: открыт, черновик, смержен, закрыт. Если репозиториев несколько, перед номером стоит имя репозитория: `epicbot#88`.

Файлы PR берутся из **локального git**, а не с GitHub: `git diff --raw -M <merge-base> <head>`, то же сравнение, что в диффе. Поэтому дерево совпадает с тем, что откроется по клику, и видны переименования. Если коммитов PR локально нет, расширение делает `git fetch <remote> refs/pull/N/head <base>`.

Файлы сгруппированы по папкам, цепочки из одной папки схлопнуты (`alembic/versions`). Сначала папки, потом файлы, по алфавиту. У файла бейдж и цвет статуса: A — добавлен, M — изменён, D — удалён, R — переименован. Клик открывает дифф, у переименованного файла слева старый путь.

Кнопка ⟳ в заголовке панели обновляет списки с GitHub, кнопка 🌐 у PR открывает его на GitHub.

## Viewed

У файлов и папок есть чекбокс Viewed. Отметки хранятся **только локально** (в `globalState` VS Code) и на GitHub не уходят.

Для каждого файла запоминается blob SHA. Если новый пуш поменял файл, отметка снимается сама, как на GitHub. Отметка папки ставится на все файлы внутри, а папка отмечена, когда отмечены все её файлы.

## Push

Если в репозитории есть локальная ветка PR, у PR появляется кнопка push ☁↑, а в описании `↑N` — сколько локальных коммитов ещё нет в PR. N считается от головы PR на GitHub (`git rev-list --count <headRefOid>..<ветка>`), а не от `origin/<ветка>`, который может устареть.

Кнопка выполняет `git push <remote> <ветка>` из корня репозитория, с `-u`, если у ветки нет upstream. Worktree делят ветки с основным клоном, поэтому неважно, в каком worktree ветка checkout'нута. Force-push нет: если push отклонён (non-fast-forward, хук), текст ошибки показывается уведомлением. После пуша PR перечитывается с GitHub и дерево перестраивается.

У PR из форков, смерженных и закрытых кнопки нет. Нет её и у PR, чья ветка входит в `prDiffLinks.protectedBranches` (по умолчанию `main`, `master`, `develop`, `stage`): основные ветки меняются только через PR. Например, у релизного PR `stage → main` нет ни кнопки, ни `↑N`, а команда push, вызванная в обход меню, выдаёт ошибку и ничего не пушит.

Пока панель открыта, расширение раз в 5 секунд читает локальные ветки (`git for-each-ref`). Поэтому `↑N` появляется сразу после коммита, сделанного в терминале. Списки с GitHub обновляются раз в 5 минут и кнопкой ⟳.

## Reveal

Клик по `.prdiff`-ссылке открывает дифф, как раньше, и добавляет PR наверх «From Links». Дерево раскрывается до файла и выделяет его, фокус остаётся в диффе. PR находится по `pr`/`url` из ссылки, у старых ссылок — по `head` (SHA или ветке). Если файла в PR уже нет (ссылка старая), выделяется сам PR.

Пока панель открыта, выделение следует за активной вкладкой диффа. Это работает и для вкладок, которые VS Code восстановил после перезапуска: PR записан в URI диффа.

Reveal переключает основной сайдбар на панель PR Diff Links. Если там же открыт чат Claude, он скроется. Можно перетащить панель во вторичный сайдбар или выключить reveal настройкой.

## Настройка

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `prDiffLinks.revealOnLinkOpen` | `true` | Раскрывать и выделять файл в дереве при клике по `.prdiff`-ссылке. Если выключить, PR всё равно попадает в «From Links», но сайдбар не переключается. |
| `prDiffLinks.protectedBranches` | `["main", "master", "develop", "stage"]` | Ветки, которые панель никогда не пушит. Если голова PR — одна из них, у PR нет кнопки push и `↑N`. Имена сравниваются точно, без масок. |

## Генератор ссылок

`bin/prdiff-link` печатает готовую Markdown-ссылку:

```bash
# по номеру PR (SHA берутся через gh, ссылки переживают мерж и удаление веток)
bin/prdiff-link --pr 82 --text "TeamMember" api/app/core/models.py 818
# → [TeamMember](/home/me/.cache/prdiff/repo/7b9cac8a8adf/api__app__core__models.py__L818.prdiff)

# то же место на GitHub, для описания PR
bin/prdiff-link --pr 82 --github --text "TeamMember" api/app/core/models.py 818
# → [TeamMember](https://github.com/<owner>/<repo>/pull/82/files#diff-<sha256(path)>R818)

# без PR, по явным ref'ам
bin/prdiff-link --refs origin/main HEAD src/app.py 42
```

Файлы `.prdiff` складываются в `~/.cache/prdiff/<repo>/<head>/`. С `--pr` в файл попадают `pr` и `url`, с `--url` — только `url`. Ответ `gh` кешируется только для смерженных и закрытых PR.

## Установка

```bash
npx @vscode/vsce package --allow-missing-repository --skip-license
code --install-extension pr-diff-links-*.vsix
```

Нужны `git` и авторизованный [`gh`](https://cli.github.com/): через него работают дерево PR и `--pr` у генератора. Сборка не требуется: расширение на чистом JavaScript без зависимостей.

Тесты чистых функций (`src/model.js`) запускаются без VS Code:

```bash
npm test
```
